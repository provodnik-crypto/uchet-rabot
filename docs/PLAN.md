## Принятые решения (ответы на вопросы этапа 0)
1. Вход — учётные записи внутри приложения (вариант «а»), логины выдаёт руководитель.
2. Мастер видит только активные работы, не материалы: **1 399** позиций.
3. Строка 08.09.2026 «Монтаж плаката новоселы наклейка»: цена и сумма 400 ₽,
   в примечании «в исходнике цена 500».
4. Часовой пояс — Тюмень, `Asia/Yekaterinburg` (UTC+5).
5. Создание учёток и смена паролей — серверная функция Supabase
   `admin-users` (на TypeScript, живёт внутри Supabase, отдельный хостинг
   не нужен). Python-сервис понадобится с этапа 5 (Excel и импорт).

## 2. Архитектура

```
Телефон (Expo Go / позже APK и iOS-сборка)
  │  supabase-js: вход, чтение справочников, RPC «отправить смену»
  ▼
Supabase (PostgreSQL + Auth + RLS)
  ▲  сервисный ключ, только на сервере
  │
Python-сервис (FastAPI + XlsxWriter + openpyxl)
  • /reports/excel           — отчёт .xlsx с нативными диаграммами
  • /price/preview, /apply   — загрузка нового прайса
  • скрипты импорта прайса 2026 и истории 2026
```

Почему так:
* Цены мастеру не приходят физически. Все денежные поля лежат в **отдельных
  таблицах**, которые RLS открывает только руководителю. Мастер отправляет
  смену через серверную функцию `submit_shift`, она сама берёт цену из прайса
  и пишет её в денежную таблицу. Ответ функции денег не содержит.
* XlsxWriter — самый надёжный способ сделать настоящие диаграммы Excel.
  Более простого варианта с тем же результатом нет: в JS нативные диаграммы
  умеет только платная версия SheetJS.
* Вход по логину: Supabase Auth требует e-mail, поэтому логин `kolya`
  превращается внутри в `kolya@uchet.local`. Мастер видит только поле «Логин».

## 3. Схема базы данных

Деньги — `bigint` в копейках (`*_kop`). Объём — `numeric(12,3)`.
Время дня считаем в часовом поясе магазина: `Asia/Yekaterinburg` (Тюмень).

### Справочники
| Таблица | Поля | Кто видит |
|---|---|---|
| `employees` | id, first_name, last_initial (одна буква), display_name («Иван П.», собирает база), icon (значок 1–12, вместо фото), role (`master`/`manager`/`service`), user_id → auth.users, login, is_active, in_output_chart | все (без лишнего) |
| `units` | id, code (`шт`,`м²`,`м`,`м³`,`т`,`кг`,`км`,`ч`,`чел.-ч`), integer_only, sort | все |
| `departments` | id, name (уникально без учёта регистра), is_default, sort, is_active | все |
| `price_items` | id, source_id (id из CSV), full_name, short_name, category, subcategory, unit_id, is_material, is_active, origin (`csv`/`manual`), source_block, source_row, поиск (pg_trgm) | мастер: только `is_active and not is_material` |
| `price_lists` | id, title («Прайс 2026»), valid_from, file_name, uploaded_by, applied_at, stats (jsonb: изменено/добавлено/выключено) | руководитель |
| `price_item_prices` | price_item_id, price_list_id, price_kop, valid_from | **только руководитель** |
| `requests` | id, number (`^(RFS\|INC)\d{6}_\d{4}$`, уникально), subject, source (`manual`/`itsm`), store_id, service, operation, description (очищено от телефонов и ФИО), itsm_status, registered_at, requester («Имя Ф. (ldap)»), is_open, assignee_id / to_contractor | мастер: всё, кроме requester (через `open_requests` — «Имя Ф.»); детали — руководитель |
| `stores` | id, code (`031`), name («Тюмень 1»); у сотрудника store_id | все |
| `work_calendar` | day, is_workday — праздники в будни и рабочие субботы (2026–2027) | все |
| `request_imports` | кто, когда, окно дат, сколько строк: в файле, новых, уже было, вне окна, с ошибками, закрыто. Без содержимого файла | руководитель |

### Журнал
| Таблица | Поля | Кто видит |
|---|---|---|
| `shifts` | id, work_date, author_id, submitted_at, status (`draft`/`submitted`), client_uuid (защита от двойной отправки) | мастер: свои и где он исполнитель |
| `work_entries` | id, shift_id, request_id?, department_id, price_item_id?, custom_name?, unit_id, quantity, note, status (`priced`/`pending`/`rejected`), reject_comment, is_imported | мастер: где он исполнитель/автор |
| `entry_performers` | entry_id, employee_id, position (1 — первый), share (доля, по умолчанию 1/n) | мастер: свои записи |
| `entry_money` | entry_id, unit_price_kop, total_kop, price_source (`price_list`/`manual`/`import`), priced_by, priced_at | **только руководитель** |
| `performer_money` | entry_id, employee_id, share_kop | **только руководитель** |

Правила, зашитые в базу:
* `quantity > 0`; для единиц с `integer_only` — только целое (триггер).
* `sum(share_kop) = total_kop` по каждой записи (пересчёт триггером, остаток
  копеек — первому исполнителю).
* Цена берётся из `price_item_prices` на дату работы и **копируется** в
  `entry_money`. Новый прайс прошлые записи не меняет.
* Мастер может менять смену только в день отправки; потом — только руководитель.
* Отчёты считают только `status = 'priced'`; число `pending` выводится отдельно.

### Представления и функции
* `v_my_entries` — журнал мастера без денег (для истории).
* `search_price_items(q, category)` — поиск по подстроке и словам, без цен.
* `my_frequent_items()`, `my_recent_items()`, `my_recent_requests()`.
* `suggest_custom_names(q)` — похожие позиции прайса и ранее оценённые работы
  вне прайса (только названия).
* `submit_shift(payload jsonb)` — проверяет и сохраняет смену, подставляет цены.
* Для руководителя: `v_entries_full`, `report_by_employee(from,to)`,
  `report_by_month(from,to)`, `price_entry(...)`, `reject_entry(...)`,
  `replace_with_price_item(...)`.

## 4. Экраны

### Мастер
1. **Вход** — логин, пароль; сессия сохраняется.
2. **Главная** — большая жёлтая кнопка «Закрыть смену», незаконченный черновик,
   уведомление об отклонённых работах, ссылка «Моя история».
3. **Дата смены** — «Сегодня» / «Вчера» (две большие кнопки).
4. **Заявка** — `RFS` / `INC` переключателем, мастер набирает 10 цифр
   (`260423` `2283`), подчёркивание ставится само; недавние номера чипами;
   кнопка «Без заявки».
5. **Выбор работы** — строка поиска сверху; вкладки «Часто», «Недавние»,
   «Категории»; в списке короткое название + категория мелко; внизу всегда
   кнопка «Работы нет в прайсе».
6. **Работа** — отдел (по умолчанию последний выбранный, иначе «Магазин»),
   объём с единицей, исполнители (я + чипы напарников), примечание.
7. **Работа вне прайса** — название с подсказками похожих, единица чипами,
   объём, исполнители, примечание.
8. **Список смены** — работы, сгруппированные по заявкам; «+ работа»,
   «+ другая заявка»; удаление свайпом.
9. **Проверка** — список без рублей → «Отправить»; при ошибке «Повторить».
   Черновик хранится на телефоне до успешной отправки.
10. **История** — смены и работы со статусами «Принято», «На оценке»,
    «Отклонено» (с комментарием и кнопкой «Исправить»).

### Руководитель
1. **Главная** — счётчик «На оценке», сумма за текущий месяц, строка
   «без цены: N работ», кнопки разделов.
2. **На оценке** — очередь; карточка: назначить цену (с подсказкой прошлой
   цены), галочка «Добавить в прайс», заменить на позицию прайса, отклонить
   с комментарием.
3. **Работы** — список с фильтрами: период, сотрудник, отдел, заявка; правка
   записи.
4. **Сводка** — по сотрудникам за период: сумма, число работ, число смен.
5. **По месяцам** — суммы по месяцам + простая диаграмма.
6. **Выгрузка в Excel** — период → файл → меню «Поделиться».
7. **Справочники**: Сотрудники (создать учётку, сбросить пароль, выключить),
   Отделы, Заявки (дозаполнить тему), Прайс (поиск,
   правка цены и единицы, включить/выключить), Загрузка прайса (файл →
   дата начала действия → предпросмотр → «Применить»), Версии прайса.

## 5. Excel-отчёт (XlsxWriter)
1. «Сотрудники» — таблица + столбчатая диаграмма по убыванию
   («Не указан» в диаграмму не входит).
2. «Итого за месяц» — месяц/сумма + столбчатая диаграмма + диаграмма
   с накоплением по сотрудникам.
3. «Основной подсчет» — Дата, Отдел, Заявка, Наименование работ, Ед. измерения,
   Кол-во, Стоимость за ед., Стоимость общая, Примечание, Исполнитель;
   по строке на исполнителя с его долей; автофильтр, закреплённая шапка.
4. «По видам работ» — объёмы и суммы по работам и по категориям + диаграмма.

Автотест сверяет итоги листов с базой до копейки и проверяет файл openpyxl.

## 7. Что нужно для работы из облачной сессии
Локального компьютера нет, поэтому всё делается из этой сессии. Нужны:
1. Аккаунт **Supabase** (бесплатный) и созданный проект.
2. Аккаунт **Expo** (бесплатный) — для EAS Update и Expo Go.
3. Хостинг Python-сервиса (например, Render, бесплатный тариф, «засыпает»
   без запросов — первая выгрузка после паузы ~30–60 с).
4. В настройках облачного окружения: разрешить сетевой доступ к
   `*.supabase.co`, `api.supabase.com`, `expo.dev`, `*.expo.dev`, `u.expo.dev`
   и добавить ключи как переменные окружения (не в чат).
