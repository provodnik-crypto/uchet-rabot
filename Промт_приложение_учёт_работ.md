# Роль и задача
Ты — senior mobile-разработчик. Помоги мне с нуля создать мобильное приложение
для учёта работ, выполненных специалистами по ремонту в магазине. Я не
профессиональный программист, поэтому объясняй шаги запуска простыми словами
и давай готовые команды.

# Что есть сейчас (приложение заменяет этот процесс)
Сейчас учёт ведётся в Excel-файле с макросами. К промту приложены два файла:
- `price_2026_max.csv` — очищенный прайс, собранный из листа «Актуальный
  прайс 2026»: 2 907 работ, у каждой одна цена. Это основной справочник
  работ для приложения.
- исходный файл `.xlsm` — для справки по структуре и истории.

Структура исходного файла:
- «Основной подсчет» — журнал работ: Дата, Отдел, Наименование работ,
  Ед. измерения, Кол-во, Стоимость за ед., Стоимость общая (= Кол-во × Цена),
  Примечание, Исполнитель. Около 2 000 строк с января 2023 по октябрь 2026.
- «Актуальный прайс 2026» — Наименование работ, Ед. изм., Цена.
- «Итого за месяц» — сумма работ по месяцам и столбчатая диаграмма.
- «график работ по заявкам» — открытые заявки: Номер (вида RFS260423_2283
  или INC251125_3012), Конечный потребитель, Дата регистрации, Тема,
  Состояние, Выполнение, Примечание.
- «журнал передачи смены» — пустой лист.

Проблемы текущего файла, которые приложение обязано устранить:
1. Исполнитель вписывается текстом, по-разному и сразу несколько в одну
   ячейку («Женя Володя», «Миша,Коля», «миша володя коля», «К;оля»).
   Посчитать выработку каждого сотрудника невозможно.
2. У большинства строк исполнитель не указан вовсе.
3. Единицы измерения пишутся вразнобой: «Штуки», «штуки», «шт», «Метр», «м»,
   «м2», «кв».
4. Отделы пишутся в разном регистре («Плитка» / «плитка»).
5. Работы в журнале не связаны с номером заявки.
6. Наименование работы набирается вручную. В 2026 году 70 % строк журнала
   (387 из 551) — работы, которых в прайсе нет: мастер пишет название
   своими словами («сборка мебели для подиума», «Распил МДФ») и сам ставит
   цену. Одна и та же работа записана по-разному и с разной ценой.

# Суть продукта
Мастера в конце смены отмечают, какие работы и в каком объёме они выполнили
по заявкам. Приложение накапливает данные, подставляет цену за единицу из
прайса, считает суммы и выгружает Excel-отчёт с диаграммами: выработка
каждого сотрудника в рублях и общая сумма выполненных работ по месяцам.

# Роли
1. Мастер — вносит работы за смену, видит свою историю работ (без рублей).
   Сейчас мастеров четверо: Коля, Миша, Женя, Володя. Список должен
   редактироваться руководителем.
   Мастер НЕ видит деньги: ни цену за единицу, ни суммы, ни итоги в
   рублях — нигде в приложении. Он видит только работу, единицу измерения
   и объём. Цены и суммы не должны приходить на его устройство вообще:
   закрой их на уровне базы (отдельное представление или RLS по столбцам),
   а не просто скрывай в интерфейсе.
2. Руководитель — видит данные всех мастеров, ведёт справочники (сотрудники,
   отделы, заявки, прайс), выгружает отчёты.

# Справочники
## Прайс (из price_2026_max.csv)
Столбцы файла: id; полное_наименование; категория; подкатегория;
короткое_название; ед_изм; цена_руб; это_материал; блок_источник;
строка_в_исходном_файле; активна.
Разделитель — точка с запятой, кодировка UTF-8 с BOM.

Как получен файл (не переделывай эту очистку, используй файл как есть):
исходный лист состоял из трёх прайсов, вставленных друг под другом, из-за
чего у 1 430 работ было по 2–3 разные цены. По решению заказчика для
каждой работы взята самая высокая цена из вариантов с той же единицей
измерения. Это временный прайс до загрузки прайса 2027 года.

Особенности, которые нужно учесть при загрузке и в интерфейсе:
- Загружай все 2 907 строк, но мастеру показывай только строки, где
  `активна` = да (1 559 работ). Остальные 1 348 — работы
  из старого блока без категорий; в части из них перепутаны единицы
  измерения. Они хранятся в базе выключенными, руководитель может включить
  нужную позицию вручную, проверив единицу и цену.
- Активных позиций 1 559, поэтому выбор работы — только через поиск по
  подстроке и по категориям, с блоками «Часто используемые» и «Недавние»
  для конкретного мастера. Длинный список без поиска недопустим.
- Категория закодирована в названии через «: » (например, «Внутренние
  инженерные сети: Электроснабжение и освещение: Монтаж эвакуационных
  светильников»). В CSV она уже разобрана на столбцы `категория`,
  `подкатегория`, `короткое_название`. В списке показывай короткое
  название, категорию — мелким шрифтом под ним.
- Единицы в CSV приведены к единому виду: шт, м², м, м³, т, кг, км, ч,
  чел.-ч. В базе храни единицы отдельным справочником.
- Позиции с `это_материал` = да — материалы, а не работы. Мастер вносит
  только работы: материалы ему не показываются и в поиске не участвуют.
  В базе они хранятся выключенными.
- Часть названий в исходном файле обрезана примерно на 120 символах — это
  не ошибка импорта, оставляй как есть.
- Руководитель должен уметь загружать новый прайс файлом (xlsx или csv)
  и править отдельные позиции вручную. Ближайшая загрузка — прайс 2027
  года. При загрузке: показать предпросмотр (сколько цен изменится,
  сколько работ добавится, сколько исчезнет) и применить только после
  подтверждения; новые цены действуют с указанной даты и не меняют уже
  внесённые работы; исчезнувшие из прайса работы выключаются, а не
  удаляются; история версий прайса сохраняется.

## Отделы
Магазин, Плитка, Декор, Сантехника, Водоснабжение, Электротовары,
Электроинструменты. Выбор из списка, ручной ввод запрещён. По умолчанию —
«Магазин» (так заполнено 96 % строк).

## Заявки
Номер заявки (формат RFS260423_2283 / INC251125_3012), заявитель, дата
регистрации, тема, состояние, примечание.
Мастер вводит номер заявки сам, с клавиатуры. Справочник заявок
пополняется автоматически из введённых номеров; остальные поля (заявитель,
тема, состояние) необязательны, их при желании заполняет руководитель.
- Проверяй формат: префикс RFS или INC, шесть цифр даты, подчёркивание,
  четыре цифры. Префикс и подчёркивание подставляй сам, чтобы мастер
  набирал только цифры. При неверном формате — понятная подсказка.
- Показывай последние номера, которые вводил этот мастер, для выбора в
  одно касание.
- Работа может быть внесена и без заявки (плановые работы) — кнопка «Без
  заявки», поле остаётся пустым.

# Сценарий мастера (главный, должен занимать не больше 1–2 минут)
1. Вход по логину и паролю. Учётные записи создаёт руководитель в
   приложении; самостоятельной регистрации нет. Сессия сохраняется на
   устройстве, чтобы не вводить пароль каждую смену.
   Заказчик назвал логин и пароль «корпоративными». На этапе 0 уточни у
   меня, что имеется в виду: (а) достаточно учётных записей внутри
   приложения или (б) нужен вход через корпоративную систему компании
   (Active Directory / SSO). Вариант (б) требует участия ИТ-службы
   компании; не закладывай его, пока я не подтвержу.
2. Кнопка «Закрыть смену». Дата по умолчанию — сегодня, можно выбрать
   вчерашнюю.
3. Ввод номера заявки, выбор из недавних или «Без заявки».
4. Выбор отдела (по умолчанию «Магазин»).
5. Выбор работы из прайса: поиск, категории, часто используемые. Если
   поиск ничего не дал — кнопка «Работы нет в прайсе» (см. раздел ниже).
6. Ввод объёма; единица подставляется из прайса автоматически. Цена
   подставляется на сервере и мастеру не показывается.
7. Выбор исполнителей: по умолчанию сам мастер, можно добавить напарников
   из списка. Каждый исполнитель — отдельная запись в базе, а не текст.
8. Поле «Примечание» (необязательное).
9. Можно добавить несколько работ и несколько заявок за одну смену.
10. Экран проверки: список работ с объёмами, без рублей → «Отправить».
11. Отправленную смену можно править до конца текущего дня, потом только
    руководитель.

# Работа вне прайса
Это не редкое исключение, а основной сценарий: сейчас так вносится 70 %
работ. Он должен быть таким же быстрым, как выбор из прайса.
1. Мастер нажимает «Работы нет в прайсе», вводит название, выбирает
   единицу из справочника, вводит объём, при желании — примечание. Цену
   мастер не указывает и не видит.
2. Пока мастер печатает название, показывай похожие позиции прайса и
   ранее оценённые работы вне прайса — чтобы не плодить дубли.
3. Запись получает статус «На оценке». Мастер видит её в своей истории с
   этим статусом, без суммы.
4. Руководитель видит очередь «На оценке» со счётчиком на главном экране.
   По каждой записи он может: назначить цену за единицу, заменить работу
   на позицию из прайса или отклонить с комментарием. Если такая работа
   уже оценивалась раньше, подставляй прошлую цену как подсказку.
5. При назначении цены руководитель может поставить галочку «Добавить в
   прайс» — тогда работа появляется в справочнике (категория «Добавлено
   вручную») и в следующий раз выбирается обычным способом по той же цене.
6. В сводки, отчёты и Excel попадают только оценённые записи. Количество
   записей «На оценке» показывается руководителю отдельной строкой, чтобы
   было видно, сколько работ ещё без цены.
7. Отклонённую запись мастер может исправить и отправить повторно.

# Работа, выполненная несколькими мастерами
В текущем журнале это частый случай (пары и тройки). Сумма работы делится
между исполнителями поровну (долевое деление может понадобиться позже —
храни долю отдельным полем, по умолчанию равные доли). Сумма
долей всегда равна полной стоимости работы, копейки округления относятся на
первого исполнителя. В отчёте по сотрудникам учитывается доля, в общих
итогах — полная сумма один раз.

# Сценарий руководителя
- Список работ с фильтрами: период, сотрудник, отдел, заявка.
- Сводка за период по каждому сотруднику: сумма, число работ, число смен.
- Сумма по месяцам (аналог листа «Итого за месяц»).
- Ведение справочников: сотрудники, отделы, заявки, прайс.
- Кнопка «Выгрузить в Excel» за выбранный период; файл открывается через
  стандартное меню «Поделиться».

# Excel-отчёт
Файл .xlsx с четырьмя листами:
1. «Сотрудники» — таблица по сотрудникам (сумма, число работ, число смен,
   средняя сумма за смену) и нативная столбчатая диаграмма Excel: сумма по
   сотрудникам, сортировка по убыванию.
2. «Итого за месяц» — месяц и сумма выполненных работ, столбчатая
   диаграмма по месяцам (как в текущем файле), плюс разбивка по
   сотрудникам в виде диаграммы с накоплением.
3. «Основной подсчет» — все строки в привычном порядке столбцов: Дата,
   Отдел, Заявка, Наименование работ, Ед. измерения, Кол-во, Стоимость за
   ед., Стоимость общая, Примечание, Исполнитель. Автофильтр, закреплённая
   шапка. Если исполнителей несколько — по строке на каждого с его долей.
4. «По видам работ» — объёмы и суммы по каждому виду работ и по категориям.
Диаграммы должны быть настоящими объектами Excel, а не картинками.
Большинство JS-библиотек (ExcelJS, SheetJS) нативные диаграммы не создают,
поэтому генерируй файл на сервере на Python через XlsxWriter. Если знаешь
более простой способ с тем же результатом, предложи его. Макросы в отчёте
не нужны.

# Перенос истории
Импортируй строки листа «Основной подсчет» за 2026 год как исторические данные, чтобы
помесячная динамика не обнулилась:
- строки без даты, работы или количества пропускай;
- отделы и единицы приводи к справочникам;
- цену и сумму бери из файла как есть, не пересчитывай по новому прайсу;
- работы, которых нет в прайсе, импортируй как оценённые работы вне
  прайса с названием из файла; в справочник их автоматически не добавляй;
- текст исполнителя разбирай на известных мастеров (Коля, Миша, Женя,
  Володя) с учётом регистра, опечаток и разных разделителей; сумму дели
  поровну;
- строки без исполнителя заноси на служебного сотрудника «Не указан» и не
  включай его в диаграмму выработки;
- после импорта покажи мне сверку: сумму по каждому месяцу 2026 года из
  файла и из базы. Для контроля: январь 2026 — 199 945 ₽, сентябрь 2026 —
  890 000 ₽.
Импортируй только строки с датой в 2026 году; 2023–2025 годы не переноси.

# Важные правила данных
- Цена фиксируется в строке работы в момент внесения. Изменение или
  перезагрузка прайса не пересчитывает прошлые записи.
- Объём — положительное число; для шт только целые, для остальных единиц
  допускаются дробные.
- Денежные суммы храни в копейках целым числом или в типе numeric, не в
  float.
- Мастер видит только записи, где он исполнитель; это должно быть защищено
  на уровне базы (Row Level Security), а не только интерфейса.
- Офлайн-режим не нужен: интернет есть везде. Достаточно не терять
  введённую смену при кратком обрыве связи: черновик хранится на
  устройстве до успешной отправки, при ошибке — кнопка «Повторить».

# Критерии готовности
- Мастер находит нужную работу среди 1 559 позиций не дольше чем за 10
  секунд и закрывает смену из 5 работ быстрее чем за 2 минуты.
- Работа вне прайса вносится не дольше чем за 30 секунд и не попадает в
  отчёты, пока руководитель не назначил цену.
- Под учётной записью мастера ни на одном экране и ни в одном ответе
  сервера нет цен и сумм в рублях.
- Сумма в приложении совпадает с суммой в Excel до копейки.
- Сумма долей исполнителей по каждой работе равна её полной стоимости.
- Помесячные итоги по импортированной истории совпадают со старым файлом.
- Excel открывается в Microsoft Excel без предупреждений, диаграммы
  отображаются и редактируются.
- Приложение запускается на Android и iOS из одной кодовой базы.
