# «Учёт работ» — правила для ИИ-помощника (Kimi Code и другие)

Проект раньше вёл Claude Code. **Все правила заказчика, устройство приложения и команды — в `CLAUDE.md`.
Прочитай его целиком перед любой работой и соблюдай как свои правила.** Там же ссылки на `docs/GUIDE.md`,
`docs/RUN.md` (все этапы и проверки), `docs/PLAN.md` (схема базы). Когда меняешь правила — правь `CLAUDE.md`,
этот файл только отсылает к нему.

## Что изменилось после перехода (с 10.11.2026)
* Работа идёт **на компьютере заказчика**, а не в облачной среде Claude. Ветка с кодом — `main`
  (до перехода — `claude/upbeat-wright-tta1q6`, она влита в `main`). Новую доработку вести в отдельной ветке
  `kimi/<кратко>` и вливать в `main` после проверки заказчиком.
* Ключи не лежат в репозитории. Заказчик задаёт их сам в файле `.env.local` в корне (файл в `.gitignore`,
  в git не класть, в чат не выводить):
  ```
  SUPABASE_ACCESS_TOKEN=...   # supabase.com → Account → Access Tokens
  SUPABASE_PROJECT_REF=...    # из адреса проекта https://<ref>.supabase.co
  SUPABASE_DB_PASSWORD=...    # Project Settings → Database
  EXPO_TOKEN=...              # expo.dev → Account settings → Access tokens
  ```
  Перед командами: `set -a && . ./.env.local && set +a`. Файл `app/.env` создаётся так, как описано в `CLAUDE.md`.
* Нужны: git, Node.js 20+, для тестов базы — PostgreSQL (`bash supabase/tests/run.sh`).
  Установка зависимостей: `cd app && npm ci`.
* Общение с заказчиком — по-русски, просто, по шагам; доработки по одной, перед этапом — план, вопросы
  и резервная копия (см. `CLAUDE.md`).
